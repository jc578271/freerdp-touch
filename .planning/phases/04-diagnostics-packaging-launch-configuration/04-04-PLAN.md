**GAP-01 — Unsafe XI_TouchOwnership event cast (BL-01):**
The XI_TouchOwnership switch case and the recovery-gate ownership branch both cast `cookie.cc->data` to `XIDeviceEvent*` and the switch case passes it to `xf_input_touch_remote()` which reads `event_x`/`event_y` — fields past the end of the smaller `XITouchOwnershipEvent` (sizeof 96 vs offsetof 104).

Fix in `xf_input.c`:
1. In the `case XI_TouchOwnership:` switch block (the one that currently casts to `XIDeviceEvent* deviceEvent` and calls `xf_input_touch_remote`): replace the cast with `const XITouchOwnershipEvent* ownEvent = (const XITouchOwnershipEvent*)cookie.cc->data;`. Call `XIAllowTouchEvents(xfc->display, ownEvent->deviceid, ownEvent->touchid, xfc->window->handle, XIAcceptTouch);`. Remove the call to `xf_input_touch_remote(xfc, cookie.cc->data, cookie.cc->evtype)` — ownership events must NOT be forwarded to the touch handler (it reads event_x/event_y which are out of bounds for ownership events). Keep the break.
2. In the recovery gate block where `XI_TouchOwnership` is handled alongside Begin/Update/End: when `evtype == XI_TouchOwnership`, cast to `const XITouchOwnershipEvent* ownEvent = (const XITouchOwnershipEvent*)cookie.cc->data;` and read `const int touchId = ownEvent->touchid;` instead of `XIDeviceEvent* dev` and `dev->detail`. For Begin/Update/End, keep the `XIDeviceEvent*` cast and `dev->detail` (those event types are XIDeviceEvent). Use an if/else inside the touch-type check: if evtype is XI_TouchOwnership, use the ownership event; else use XIDeviceEvent. The quarantine lookup and TouchEnd removal logic uses `touchId` in both cases. The XIAllowTouchEvents call in the ownership branch of the recovery gate uses `ownEvent->deviceid` and `ownEvent->touchid`.

**GAP-02 — Repeated cancellation permanently suppresses touch (BL-02):**
In `xf_touch_force_cancel()`, the code does `xfc->quarantinedCount = 0;` before re-adding active fingers. If called a second time after gesture state was already cleared (but before End events drain), quarantinedCount can end at 0 while `recoveryGateArmed` remains TRUE (it is only ever set TRUE, never derived from the count).

Fix in `xf_input.c`:
1. Remove the line `xfc->quarantinedCount = 0;` at the top of the quarantine section in `xf_touch_force_cancel()`. Instead, PRESERVE existing quarantined IDs. Before adding new finger IDs, deduplicate against the existing quarantinedFingers array. Each add site (savedPinchA, savedPinchB, savedMidFingerC, savedFallback, and native cctx->contacts) must check `xfc->quarantinedCount < (int)FREERDP_MAX_TOUCH_CONTACTS` and skip IDs already present in the array. The existing deduplication logic for savedMidFingerC and savedFallback already checks for duplicates — extend the same dedup check to savedPinchA and savedPinchB (they currently lack the dup check). All four saved-finger adds should use the same dedup-and-bounds-check pattern.
2. Change the final recovery-gate line from `if (xfc->quarantinedCount > 0) xfc->recoveryGateArmed = TRUE;` to `xfc->recoveryGateArmed = (xfc->quarantinedCount > 0);` — always derive the flag from the count, never leave it stale TRUE.

**GAP-03 — Bounds filter drops lifecycle End (BL-03):**
The content-bounds early return in `xf_input_touch_remote()` runs for every event type including `XI_TouchEnd`. A contact that began inside content but lifts over a letterbox border is dropped before reaching the fallback cleanup that releases Button1 or Ctrl.

Fix in `xf_input.c`:
Change the bounds gate condition from `if (x < left || x >= right || y < top || y >= bottom)` to `if (evtype == XI_TouchBegin && (x < left || x >= right || y < top || y >= bottom))`. This restricts admission bounds to Begin only; Update and End always reach `xf_input_touch_fallback()` for state cleanup. The `evtype` parameter is already available in `xf_input_touch_remote()`.

**GAP-04 — Pinch accumulation discards fractional motion (BL-04):**
`pinchAccum` is `INT32` and each `double delta` is cast to `INT32` before accumulation, truncating sub-pixel motion to zero.

Fix in `xfreerdp.h`: Change `INT32 pinchAccum;` to `double pinchAccum;` (line 331 in the working tree).

Fix in `xf_input.c`:
1. Change `xfc->pinchAccum += (INT32)delta;` to `xfc->pinchAccum += delta;` (remove the truncating cast).
2. Change `while (abs(xfc->pinchAccum) >= PINCH_WHEEL_STEP_PX)` to `while (fabs(xfc->pinchAccum) >= (double)PINCH_WHEEL_STEP_PX)`.
3. Change `if (xfc->pinchAccum > 0)` to `if (xfc->pinchAccum > 0.0)`.
4. Change `xfc->pinchAccum -= PINCH_WHEEL_STEP_PX;` to `xfc->pinchAccum -= (double)PINCH_WHEEL_STEP_PX;`.
5. Change `xfc->pinchAccum += PINCH_WHEEL_STEP_PX;` to `xfc->pinchAccum += (double)PINCH_WHEEL_STEP_PX;`.
6. Change the diagnostic format for the pinch wheel records from `accum=%d` to `accum=%.2f` and pass `xfc->pinchAccum` (a double) instead of an int. The `touch-diag:` marker prefix is preserved.
7. All `pinchAccum = 0;` reset sites (init, force_cancel, gesture end) become `pinchAccum = 0.0;` (or keep `= 0;` which is valid for double, but use `0.0` for clarity at the accumulation-reset sites).

**GAP-05 (parser) — Unchecked atoi conversion (BL-05 parser half):**
The command-line parser for `touch-long-press` and `touch-slop` uses `atoi(arg->Value)` cast to `UINT32` with no syntax, overflow, or range validation.

Fix in `client/common/cmdline.c`:
In the `CommandLineSwitchCase(arg, "touch-long-press")` and `CommandLineSwitchCase(arg, "touch-slop")` blocks: replace `(UINT32)atoi(arg->Value)` with checked conversion. For each:
1. Declare `char* endp = NULL; errno = 0;` (errno requires `#include <errno.h>` — check if already included; if not, add it near the existing includes at the top of cmdline.c).
2. Call `unsigned long val = strtoul(arg->Value, &endp, 10);`.
3. Check: `if (errno != 0 || endp == arg->Value || *endp != '\0')` → return `fail_at(arg, COMMAND_LINE_ERROR)` (reject non-numeric, empty, partial consumption, or overflow).
4. For touch-long-press: `if (val < 500 || val > 700)` → return `fail_at(arg, COMMAND_LINE_ERROR)` (enforce the same range the wrapper enforces, per D-16, D-13).
5. For touch-slop: `if (val < 4 || val > 16)` → return `fail_at(arg, COMMAND_LINE_ERROR)` (enforce the same conservative range, per D-16, D-13).
6. Pass `(UINT32)val` to `freerdp_settings_set_uint32`.
Add `#include <errno.h>` at the top of cmdline.c if it is not already present (check the existing includes first).

**GAP-10 — Fallback cancellation diagnostic contract (WR-04, latest-coordinate lifecycle store):**
The canonical `+touch-pinch-wheel-fallback` path does not populate `xfc->contacts[]` or `active_contacts`, so the existing per-contact cancel loop over `xfc->contacts[]` emits nothing for the fallback path, and the force_cancel summary reports `active_contacts=0` which is misleading. The previous approach of using saved fallback state fields with initial coordinates (lpDownX/lpDownY) reports the touch's Begin position, not its last position before cancellation.

Fix in `xfreerdp.h`: Add a diagnostic-only contact snapshot to the xfContext struct:
1. Add `typedef struct { int touchId; int x; int y; BOOL active; } xfDiagContact;` near the existing touch-related fields.
2. Add `xfDiagContact diagContacts[FREERDP_MAX_TOUCH_CONTACTS]; int diagContactCount;` to the xfContext struct. These are diagnostic-only; they do not affect gesture routing, contact mapping, or RDPEI state.

Fix in `xf_input.c`:
1. Add three static helper functions (all called only when `xfc->touchDiagEnabled` is true):
   - `static void xf_diag_contact_begin(xfContext* xfc, int touchId, int x, int y)`: find a free slot (active == FALSE) in `diagContacts[]`; if the touchId is already present and active, refresh its coordinates instead; set {touchId, x, y, active = TRUE}; increment `diagContactCount`.
   - `static void xf_diag_contact_update(xfContext* xfc, int touchId, int x, int y)`: find the active slot by touchId; refresh x and y to the LATEST coordinates; if not found, no-op (the touch was rejected at Begin).
   - `static void xf_diag_contact_end(xfContext* xfc, int touchId)`: find the active slot by touchId; set active = FALSE; decrement `diagContactCount`.
2. In `xf_input_touch_remote()`, after the bounds gate (which now only rejects Begin outside bounds) and before the call to `xf_input_touch_fallback()`, add a gated snapshot update: `if (xfc->touchDiagEnabled) { const XIDeviceEvent* dev = (const XIDeviceEvent*)data; int tid = dev->detail; int dx = (int)dev->event_x; int dy = (int)dev->event_y; switch (evtype) { case XI_TouchBegin: xf_diag_contact_begin(xfc, tid, dx, dy); break; case XI_TouchUpdate: xf_diag_contact_update(xfc, tid, dx, dy); break; case XI_TouchEnd: xf_diag_contact_end(xfc, tid); break; } }`. This captures the LATEST coordinates on every Update so a moved contact cancels at its last position.
3. In `xf_touch_force_cancel()`, before the existing `xfc->contacts[]` cancel loop, add a gated block: `if (xfc->touchDiagEnabled) { int diag_active = 0; for (int i = 0; i < FREERDP_MAX_TOUCH_CONTACTS; i++) { if (xfc->diagContacts[i].active) { diag_active++; WLog_WARN(TAG, "touch-diag: event=cancel id=%d x=%d y=%d", xfc->diagContacts[i].touchId, xfc->diagContacts[i].x, xfc->diagContacts[i].y); xfc->diagContacts[i].active = FALSE; } } xfc->diagContactCount = 0; }`. This emits exactly one Cancel per active snapshot at its last Update coordinates, then clears. Compute `diag_active` before the clearing loop so the summary can use it.
4. Update the force_cancel summary record to report `diag=` (the diagnostic snapshot active count) instead of `fallback=` from saved state fields: `if (xfc->touchDiagEnabled) WLog_WARN(TAG, "touch-diag: force_cancel ctrl=%d diag=%d native=%d quarantined=%d", xfc->ctrlHeld, diag_active, xfc->active_contacts, xfc->quarantinedCount)`. Keep `native=` (the existing `active_contacts`) and `quarantined=` as separate fields.
5. Keep the existing `xfc->contacts[]` per-contact cancel loop unchanged (it fires when native contacts exist, which does not happen in the canonical local-only path but may in other configurations).
6. The `diagContacts` array and `diagContactCount` are zeroed by the existing xfContext initialization (verify the struct is zero-allocated on context creation; if so, all active fields start FALSE and count starts 0).

All diagnostic snapshot operations are gated by `touchDiagEnabled` and are observational only — they do NOT change any gesture routing, state clearing, quarantine logic, or contact mapping. The snapshot is bounded by FREERDP_MAX_TOUCH_CONTACTS (10) and uses no dynamic allocation.
