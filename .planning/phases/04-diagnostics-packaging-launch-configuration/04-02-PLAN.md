Create `scripts/launch-touch.sh` as a Bash script (Bash is required for arrays and PIPESTATUS[0] — Pitfall 5). The wrapper owns ONLY the local-touch preset; all FreeRDP connection/session arguments pass through unchanged.

Structure:
1. Shebang `#!/usr/bin/env bash`, `set -eu`.
2. Resolve the sibling gate script source-relative: compute `script_dir` from `BASH_SOURCE[0]` (not a relative or PATH lookup) so the gate resolves correctly regardless of the caller's working directory. The gate path is `"$script_dir/check-x11-session.sh"`.
3. Parse `--mouse-only` from `$@`: iterate all args, set a `mouse_only=1` flag when `--mouse-only` is found, and build a `fwd_args` array of all remaining arguments. This preserves argument boundaries and removes only the `--mouse-only` token. Never use eval (Pitfall 6, ASVS V5).
4. Compose touch args as a Bash array (D-01, D-15):
   - Mouse-only: set `touch_args=()` (omit all touch options — D-20) and skip calibration validation entirely since no touch options are composed. Irrelevant or invalid calibration env vars must NOT cause rejection in mouse-only mode.
   - Non-mouse-only: validate calibration overrides (D-15, D-16) BEFORE composing touch args:
     - `FREERDP_TOUCH_LONG_PRESS_MS`: default 600. Accept only unsigned decimal digits. Range 500-700. Reject non-digits or out-of-range with a clear stderr message and exit 1 before invoking FreeRDP.
     - `FREERDP_TOUCH_SLOP_PX`: default 8. Accept only unsigned decimal digits. Range 4-16. Reject non-digits or out-of-range with a clear stderr message and exit 1.
     - Validation must use a digits-only check (e.g., `case "$val" in *[!0-9]*|'') reject;; esac`) and arithmetic comparison (`[ "$val" -ge 500 ] && [ "$val" -le 700 ]`).
   - Non-mouse-only touch_args: `("+touch-pinch-wheel-fallback" "/touch-long-press:${lp_ms}" "/touch-slop:${slop_px}")`
   - Never include `+multitouch` (D-01, Pitfall 3).
5. Run the native-X11 gate: `"$script_dir/check-x11-session.sh"`. Fail closed if not native X11.
6. Normal mode (FREERDP_TOUCH_DIAG unset or not "1"): `exec /usr/bin/xfreerdp3 "${touch_args[@]}" "${fwd_args[@]}"` — direct exec, no tee, no subshell (D-05).
7. Diagnostic mode (FREERDP_TOUCH_DIAG=1):
   - Set `umask 077` BEFORE creating any directory or file (D-06).
   - Create log directory: `log_dir="${XDG_STATE_HOME:-$HOME/.local/state}/freerdp-touch"`; `mkdir -p "$log_dir"`.
   - Create log via mktemp inside the state directory: `log_path="$(mktemp "$log_dir/touch-XXXXXX.log")"` — not a predictable filename (D-05, D-06).
   - Verify directory permissions are 0700 and file permissions are 0600 (umask 077 ensures this).
   - Run with tee: `/usr/bin/xfreerdp3 "${touch_args[@]}" "${fwd_args[@]}" 2>&1 | tee "$log_path"`; `exit "${PIPESTATUS[0]}"` (Pitfall 5: preserve client exit status, not tee's).
   - Do NOT echo the constructed command, do NOT set WLOG_LEVEL=DEBUG, do NOT enable shell xtrace (D-05, D-06, Pitfall 6).
8. The wrapper must NOT read, store, prompt for, or echo passwords or connection credentials (D-19). FreeRDP's existing prompt handles authentication.

Make the script executable: `chmod +x scripts/launch-touch.sh`.

Do NOT add a production test hook or test-specific env var to the wrapper. The test approach uses a temporary rewritten copy with mocked gate and client paths: create a temp directory, copy the wrapper there, create a mock check-x11-session.sh that exits 0, create a mock xfreerdp3 that echoes its args to stderr and exits with a controlled status, then sed the wrapper copy to replace /usr/bin/xfreerdp3 with the mock path. Run the rewritten copy with various inputs and assert all modes and forwarding behavior.
