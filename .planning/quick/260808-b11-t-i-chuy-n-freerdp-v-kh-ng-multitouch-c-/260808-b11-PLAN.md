<objective>
Fix the two-finger gesture misclassifier in the local-only fallback path so that an axial two-finger swipe (fingers placed vertically and swiped down) classifies as scroll instead of pinch zoom, without weakening true pinch recognition.

Purpose: With `+multitouch` off and `+touch-pinch-wheel-fallback` on, all two-finger disambiguation runs through `xf_input_two_finger_resolve`. The pinch claim is checked first against `PINCH_DEADBAND_PX` (8px) and the scroll claim against the pan deadband (also default 8). On a real touchscreen the first TouchUpdate carries only one finger's movement; for an axial (vertical/horizontal) finger placement that single finger changes the inter-finger distance by the full delta D while it moves the midpoint by only D/2. So `pinchDelta` reaches 8px (at D=8) before `panDelta` reaches 8px (needs D=16), and pinch — checked first — always wins the race. The fix is a root-cause dominance guard, not a threshold tweak: require pinch's distance change to exceed the midpoint movement by the geometric transient ratio before pinch can claim.

Output: A ~3-line condition change plus one named constant in xf_input.c, a standalone regression model that pins the disambiguation rule for axial/diagonal scroll and symmetric pinch, and a static check that the dominance guard is present in the real source. Build stays green.
</objective>
