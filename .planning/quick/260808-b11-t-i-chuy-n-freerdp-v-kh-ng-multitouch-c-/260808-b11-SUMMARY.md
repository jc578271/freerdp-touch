# Phase 03 Plan 260808-b11: Fix Two-Finger Axial Swipe Misclassification

**One-liner:** Added a 2.5x pinch-dominance ratio guard to `xf_input_two_finger_resolve` so axial two-finger swipes classify as scroll instead of pinch zoom, without weakening true pinch recognition.

## Implementation

The pinch claim in `xf_input_two_finger_resolve` was checked first against only `PINCH_DEADBAND_PX` (8px). On a real touchscreen the first `TouchUpdate` carries only one finger's movement; for an axial finger placement that single finger changes the inter-finger distance by the full delta D while moving the midpoint by only D/2. With both deadbands at 8px and pinch checked first, pinch always won the race.

**Fix:** A new `#define PINCH_DOMINANCE_RATIO 2.5` constant and an additional conjunct in the pinch claim: `pinchDelta > PINCH_DOMINANCE_RATIO * panDelta`. This requires pinch's distance change to dominate midpoint movement by >2.5x before pinch can claim.

**Ratio choice (2.5, not 2.0):** The ideal geometric ratio for a one-finger-first axial transient is 2.0 (pinchDelta=D, panDelta=D/2), but the real code computes midpoint coordinates with integer division (`int currentMidY = (ay+by)/2`), which truncates D/2. At the claim threshold, a 9px update gives `pinchDelta=9, int panDelta=4`, and `9 > 2.0*4=8` still claims pinch. The +0.5 margin (2.5) covers integer midpoint quantization at every pixel boundary within the pinching range.

- Axial two-finger swipe: `pinchDelta ~ D`, integer `panDelta ~ floor(D/2)` → ratio ~ 2.0-2.25 → pinch rejected with 2.5 guard, scroll claims when `panDelta >= 8px`.
- True pinch: `pinchDelta` grows, `panDelta ~ 0` → dominance holds → pinch claims within the existing deadband.
- Diagonal/parallel scroll: `pinchDelta ~ 0`, `panDelta` grows → scroll claims, unchanged.

**Changes:**
- `PINCH_DOMINANCE_RATIO 2.5` constant added after `PINCH_DEADBAND_PX` (line ~68)
- Pinch claim condition: `pinchDelta >= (double)PINCH_DEADBAND_PX && pinchDelta > (double)PINCH_DOMINANCE_RATIO * panDelta` (lines ~973-974)
- Comment documents the integer-midpoint quantization rationale

**Untouched:** `PINCH_DEADBAND_PX` value (8), `xf_input_pinch_update` baseline-deadband usage, scroll claim block, one-finger/three-finger/lifecycle paths, no new gesture state or settings slot.

## Deviations from Plan

### Coordinator correction: Integer-midpoint quantization

**Found during:** Post-implementation review (coordinator)
**Issue:** The plan specified `PINCH_DOMINANCE_RATIO 2.0` based on the ideal geometric ratio (pinchDelta=D, panDelta=D/2), but `currentMidX/Y` are computed with integer division in the real source. At odd-pixel displacements (e.g., 9px vertical), integer truncation gives panDelta=4 instead of 4.5, so `9 > 2.0*4=8` still claims pinch — the same class of bug the ratio was meant to fix.
**Fix:** Bumped `PINCH_DOMINANCE_RATIO` from 2.0 to 2.5, adding a 0.5 safety margin over the ideal 2.0 to cover integer midpoint quantization at every pixel boundary. Updated `test_scroll_classifier.c` to use integer-division midpoints (matching the source) and added the 9px gate case + sequential 8px-per-finger symmetric pinch case.
**Files modified:** `xf_input.c` (constant + comment), `test_scroll_classifier.c` (model + new cases), `SUMMARY.md` (ratio, decisions, deviation note)
