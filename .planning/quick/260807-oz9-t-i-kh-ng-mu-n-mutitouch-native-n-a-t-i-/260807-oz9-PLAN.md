<objective>
Stop forwarding touchscreen contacts as native RDPEI multitouch. Make the client-owned fallback gesture path the only touch path, and add two-finger middle-button pan disambiguated from pinch: pinch (fingers moving apart/together) holds Ctrl and emits mouse-wheel; pan (fingers moving together) presses and holds the middle button while the pointer follows the pan motion.

Purpose: The user no longer wants native multitouch. All touch is consumed locally by xfreerdp3 and translated to desktop input: one-finger tap/press -> left click/drag, long press -> right click, two-finger pan -> middle-button drag with pointer following, pinch -> Ctrl + wheel. The existing xf_input_touch_fallback already implements the one-finger gestures and the pinch Ctrl+wheel path; the pivot removes the native RDPEI path so fallback becomes the sole owner, then adds the missing two-finger pan.

Output: Patched build tree that compiles and runs with all four touch interactions produced from local gesture recognition; no RDPEI touch contacts forwarded.
</objective>
